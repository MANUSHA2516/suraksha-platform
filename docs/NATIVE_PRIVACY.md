# Native privacy implementation

Internal calculator, notes and weather fallback surfaces are accessible while sensitive navigation is locked. Long-press the utility's display/header for 1.5 seconds to reveal the PIN gate. The PIN is verified by the server, with Argon2 hashing and temporary attempt lockout. Optional device biometrics use Expo LocalAuthentication. Backgrounding clears query memory and replaces the sensitive navigator with the disguise. These measures do not conceal the application from operating-system settings, installed-app lists, backups or forensic inspection.

Android: `apps/mobile/plugins/with-disguise.cjs` adds four launcher activity aliases, code-native vector icons and a Kotlin React Native module to generated native projects. The runtime provider enables the selected alias before disabling others. This uses Android's documented [activity-alias mechanism](https://developer.android.com/guide/topics/manifest/activity-alias-element). Expo Go does not contain this module and explicitly reports internal-only behavior. Config transformation is tested and Android prebuild generated the aliases, module registration and media permissions; native compilation/device and launcher-cache behavior still require Android SDK/emulator verification. No claim of device-tested concealment is made.

Apple provides [setAlternateIconName](https://developer.apple.com/documentation/uikit/uiapplication/setalternateiconname(_:completionhandler:)) for predeclared alternate icons, subject to platform support; it is not an arbitrary runtime application-name API. This prototype does not configure alternate iOS icon assets or promise runtime name changes. Internal disguise and the native biometric prompt are available; iOS signed builds/device validation require macOS/Xcode and signing.

A complete native deployment must additionally validate app-switcher snapshot protection, accessibility behavior of hidden entry, notification previews, lockout/recovery, background location, device token storage, permission interruption and imports. PIN unlock currently needs connectivity. A short-term access token is kept only in JS memory; the rotating refresh credential is kept in native SecureStore. PIN digits are never stored in a plaintext preference.

Evidence capture uses native camera/microphone permission prompts and private file imports. A user-initiated system picker gets a bounded activity handoff so Android activity changes do not discard its result; normal app backgrounding still relocks. Decrypted audio/video previews use private cache files erased on unmount; interrupted preview files are purged on next startup. This is not guaranteed forensic erasure. Native recorder/camera caches and actual device interruption behavior still need device validation.
